# 动作序列回放

默认离线预览，只有 `--execute` 才发送 MoveJ 请求。不自动使能、掉使能、标零。记录器命名后会直接打印可复制的预览及执行命令。

## 新手动点格式

记录器每次回车保存一个点，按 q 结束后命名，例如 lift_001。预览：

```zsh
cd ~/lbot_ws
/usr/bin/python3 tools/replay_workpoints.py recordings/你的记录目录/events.jsonl --arm right --to lift_001 --move-to-start
```

确认实物已使能、当前到起点和相邻点间路径无障碍后，实际执行：

```zsh
source /opt/ros/jazzy/setup.zsh
source ~/lbot_ws/install/setup.zsh
/usr/bin/python3 tools/replay_workpoints.py recordings/你的记录目录/events.jsonl --arm right --to lift_001 --move-to-start --execute
```

`--arm left` 为左臂；另一臂须保持记录时的姿态。本版本不支持双臂同时变化的协同回放。

- 选择 sequence_id（如 sequence_001）或唯一 label。自动按 point_ids 顺序执行，从第一个点开始，不使用 --from。
- 每个手动点均保留，即使相邻点很近。不会自动补中间记录点。控制器通过 MoveJ 在相邻关节目标之间插值，不保证末端走直线或复现手动绕行。
- 手动点允许长时间间隔和大于 0.2 rad 的关节差，不套用连续采样的 --max-gap、--max-step 阈值。这是显式记录的稀疏目标，不代表点间路径经过碰撞检查。
- 首个点是起点；启用 --move-to-start 时先接近。只有一个点时只需接近这个点。

## 起点接近

--move-to-start 默认关闭。不启用时当前姿态须在起点容差 0.05 rad 内，否则不运动。

启用后，如果选定臂偏离起点，先发一次阻塞 MoveJ，速度默认 --approach-speed 0.15 rad/s，加速度 --approach-accel 0.15 rad/s²，均限制最高 0.3。确认服务成功且反馈到位后，再执行其余点。另一臂不自动修正。

接近起点是额外的关节空间运动，不是记录路径倒放，不是末端直线，没有碰撞规划。执行前必须确认这段路径。接近也适用 --timeout（默认每次请求 30 秒）。

## 另一只臂校验（可跳过）

默认回放要求另一只臂停在记录时姿态：规划时检查它在整条记录中静止（>0.05 rad 拒绝），执行时每步比对实时姿态，偏离 `--start-tolerance`（默认 0.05 rad）即中止，防止回放臂碰到它。

确认另一只臂全程不会与回放路径干涉、且已固定时，可加 `--ignore-other-arm` 同时跳过这两项检查。跳过期间脚本完全不读取另一只臂姿态，碰撞风险由操作者承担；活动臂自身的关节名称/坐标系、到位误差检查仍然生效。

## 执行时反馈新鲜度

执行阶段只校验需要的关节话题（活动臂 + 另一臂；加 `--ignore-other-arm` 后只有活动臂），不等待 pose_states——位姿话题运动时发布更慢（实测静止约 42 Hz，运动时更低），纳入检查会误报 skew。参数：`--max-age`（默认 0.5 s，最新一帧距本地接收时刻的最大延迟）、`--max-skew`（默认 0.15 s，左右关节话题最新帧接收时刻之差）。这里的新鲜度仅指本地接收，驱动重打缓存时间戳的情况无法靠它识别。

## 速度与检查

回放默认 --speed 0.3 rad/s、--accel 0.5 rad/s²，均限制最高 0.5。每步阻塞等待业务 success，并检查反馈到位误差（默认 --reached-tolerance 0.03 rad）。低速时伺服可能停在容差外几毫弧度（实测约 0.033 rad），脚本会自动重发同一目标补点，最多 3 次；残差大于 0.1 rad 或 3 倍容差时不重试，直接报各关节残差（说明没动或被挡住）。若该硬件反复差一点，可适当放宽 `--reached-tolerance`（如 0.05）。检查双臂反馈新鲜度、数值、关节名称顺序、坐标系和另一臂姿态。

接口文档《机械臂控制接口文档v1.0.5》5.3.1 规定 MoveJ 参数范围速度 0–20 rad/s、加速度 0–20 rad/s²，这是 SDK 参数范围而非本实物已验证运行速度。5.3.4 的 50–200 Hz 是关节跟随频率；文档没有给出 MoveJ 最大下发频率。本脚本使用阻塞 MoveJ，实际请求频率随运动完成时间变化。

## 旧记录兼容

- schema_version=1：--to lift，可选 --from start；不指定起点时从首个有效采样开始，明确报告忽略的启动无效数据。
- schema_version=2：--to lift_001 自动选择本条记录起点，不允许跨记录拼接。
- 连续采样旧格式仍检查中途无效、0.5 秒采样间隔和默认 0.2 rad 相邻跳变，并合并静止附近采样（--min-step 默认 0.002 rad，设 0 保留全部）。检查在合并前完成。手动格式不合并。

## 中止与限制

服务失败、超时、反馈异常或 Ctrl+C 会停止后续下发，但不能取消在途 MoveJ。必要时使用实体急停。不会自动掉使能，以免失去支撑。

没有碰撞规划、模型限位验证、工具/负载一致性验证和硬件反馈新鲜度保证。驱动给缓存数据重打时间戳，不能据此判定底层反馈始终有效。脚本读取范围不含使能、故障、温度和灵巧手反馈。

测试：加载 ROS2 环境后在 tools 目录执行 `/usr/bin/python3 -m unittest -v test_record_workpoints.py test_replay_workpoints.py`。测试使用离线数据和替身服务，不连接实物。
