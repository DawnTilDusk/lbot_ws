# 工作点轨迹回放

`replay_workpoints.py` 读取 `record_workpoints.py` 的 JSONL 文件。默认离线预览；只有 `--execute` 才创建 ROS2 节点并发送 MoveJ 请求。不自动使能、掉使能、回零、标零或从任意姿态接近起点。

## 先记录一段

1. 运行记录器，在起点第一次直接回车，开始采样。
2. 缓慢移动单臂，另一臂保持不动。
3. 第二次直接回车停止，再输入 `lift` 回车，得到 `lift_001`。
4. 继续录下一条，或 `:q` 退出。

## 预览

```zsh
cd ~/lbot_ws
/usr/bin/python3 tools/replay_workpoints.py recordings/你的记录目录/events.jsonl --arm right --to lift_001
```

新格式自动选择该条记录起点，不需要 `--from`，不允许跨不同记录连接路径。旧格式仍支持 `--from start --to lift`，未指定起点时从首个有效采样开始。脚本会明确报告丢弃的启动无效样本数；中途无效样本拒绝。

## 实物执行

先检查预览结果、工作区、工具和负载是否与记录一致，确认实体急停可用。按设备支持的操作方式到达记录起点，确认支撑及使能状态，再执行：

```zsh
source /opt/ros/jazzy/setup.zsh
source ~/lbot_ws/install/setup.zsh
/usr/bin/python3 tools/replay_workpoints.py recordings/你的记录目录/events.jsonl --arm right --to lift_001 --execute
```

当前两臂姿态必须匹配记录起点，最大关节误差默认 0.05 rad；不能把该阈值调大来跳过起点检查。若你还在 `lift` 终点，本脚本不会自动把机械臂送回 `start`。回程需要另录或另行审核路径。

## 行为和限制

- 单臂逐个采样关节点调用阻塞 MoveJ，检查服务 `success`，再检查位置误差（默认 0.03 rad）。默认速度 0.3 rad/s、加速度 0.5 rad/s²；两者最高允许 0.5。
- 先验证选中区间全部采样，再合并距离上个保留点小于 0.002 rad 的静止附近采样，始终保留起终点，并限制合并后的关节跳变。`--min-step 0` 可保留全部点。减少请求会轻微改变插值路径，不保证精确复现。原始时间用于完整性检查，不用于复现原始速度；控制器负责每两个关节点之间插值，可能逐点停顿，笛卡尔路径并非精确手动轨迹。
- 轨迹不能存在中途无效状态、关节顺序/坐标系变化、超过 0.5 秒的采样空洞；相邻关节变化默认最多 0.2 rad。所有关节数值必须有限。
- 另一臂在记录中移动超过 0.05 rad 时拒绝，此版本不支持双臂同步回放。执行时也检查另一臂仍接近起点。
- `--max-step` 和 `--max-gap` 可用于离线分析，不应仅为了让实物执行通过而调大。它们不是碰撞检测或硬件限位。
- 无碰撞规划、模型限位校验、使能/故障反馈和硬件反馈新鲜度保证。继承记录器所述驱动缓存时间戳限制；新 ROS 时间戳不保证新硬件反馈。
- 服务超时、异常或 Ctrl+C 会停止下发后续命令，但已经发送的 MoveJ 可能仍执行。ROS 服务不提供取消语义；紧急情况使用实体急停。脚本不自动掉使能，避免支撑突然丢失。

## 文档中的“最大速度”

依据随仓库提供的 `开发资源/机械臂控制接口文档v1.0.5.pdf`：

- 5.3.1：MoveJ 的速度参数范围 0–20 rad/s，加速度 0–20 rad/s²。这是 SDK 参数范围，不是本实物、工具和负载已经验证的速度。
- 5.3.4：关节跟随接口通信频率 50–200 Hz。
- 5.2：状态监控频率 50 Hz。
- 文档没有给出 MoveJ 最大下发频率。当前脚本仍用阻塞 MoveJ，不是关节跟随接口，因此不能声称它以 200 Hz 下发。

本次提速：默认速度 0.15→0.3 rad/s，加速度 0.15→0.5 rad/s²，减少静止附近重复请求。继续逐步检查业务返回和到位反馈，不切换为非阻塞请求堆积。每秒请求数由实际运动完成时间决定。

对旧文件 `20260908_133009_736558` 的离线预览：189 个原始状态（188 个目标）变为 74 个保留状态（73 个目标），起终点保持。此数值不是实物运行时间测量。
